# GIT-004 — linked repository avatar and heading permalink are unnamed

Severity: Medium. Status: confirmed, not filed. axe `link-name` impact: serious.

Environment: official Gitea 28.2.0, initialized repository/README, anonymous Chromium, axe-core 4.11.1.

1. Open `/qaowner/journeys`.
2. Inspect `.avatar-stack > a` and the README heading permalink `.anchor`.
3. Run axe `link-name`.

Expected: every focusable link has a programmatic name identifying its target or action.

Actual: the author avatar link contains an image with `alt=""` and visual `title="qaowner"`, while the link has no accessible text/name. The recorded heading anchor is also unnamed. axe reports both nodes.

Impact: assistive-technology link-list navigation cannot identify these link targets. An adjacent author-name link does not automatically name a separate avatar link.

Evidence: [HTML and selectors](../evidence/axe-findings.json), [repository screenshot](../evidence/screenshots/journeys-axe-qaowner-journeys.png), [JUnit](../evidence/playwright-junit.xml).

Duplicate check: `accessible name` and `avatar accessibility` searches found no matching current report. [Historical missing-alt issue](https://github.com/go-gitea/gitea/issues/20606) describes missing attributes; this reproduction has empty alt inside an independently focusable link. Link this history so maintainers can decide whether to consolidate. [Search record](upstream-search.md).

Fix direction: contextual names for the avatar and heading permalink, with template/renderer regressions. Two source locations are grouped as one link-naming defect class.
