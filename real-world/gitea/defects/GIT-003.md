# GIT-003 — default light-theme text has insufficient contrast

Severity: Medium. Status: confirmed, not filed.

Environment: unmodified Gitea 28.2.0, Chromium, axe-core 4.11.1, default light theme. Exploratory Auto/dark observations are separate from these recorded light-theme measurements.

1. Open `/` in the light theme.
2. Inspect `run the binary` in the Easy to install paragraph.
3. Run axe `color-contrast` or compare computed text/background colors.
4. Repeat scans on login, Explore, repository and issue-list pages.

Expected: normal body text meets at least 4.5:1 WCAG AA contrast.

Actual: the home link uses `#609926` on `#ffffff`, 16px normal text, measured **3.45:1**. Other links/text/buttons fail on all remaining scanned routes; exact nodes/colors/ratios are retained in the raw evidence.

Impact: low-vision users can struggle to read text and distinguish linked actions. This is a measured contrast finding, not a full accessibility certification.

Evidence: [axe ratios and nodes](../evidence/axe-findings.json), [login screenshot](../evidence/screenshots/journeys-axe-user-login.png), [JUnit](../evidence/playwright-junit.xml). Reproduced locally and in CI.

Duplicate check: open/closed `contrast` issue search returned no results. [Dated search record](upstream-search.md); recheck before filing.

Fix direction: adjust affected light-theme tokens and retest normal/hover/disabled/dark contexts. Multiple theme contexts make this broader than the isolated contract fix.
