# GIT-002 — collapsed dropdowns expose menus without required children

Severity: Medium. Status: confirmed, not filed. axe rule impact: critical.

Environment: official Gitea 28.2.0 image, Chromium, axe-core 4.11.1; local Windows and Ubuntu CI. [Digest](../evidence/environment.json).

1. Open `/user/login` anonymously.
2. Leave theme/language selectors collapsed.
3. Run axe with WCAG 2 A/AA and 2.1 AA tags or inspect the accessibility tree.
4. Repeat on home, Explore, repository and issue-list pages.

Expected: valid trigger/popup roles and expanded state; a collapsed trigger should not expose an empty menu requiring menuitem children.

Actual: `#footer-theme-selector` and language `.upward` have `role="menu"`, `aria-haspopup=""`, `aria-expanded="false"`; visible content is a span and popup children are hidden. axe reports `aria-required-children` on all five routes. Other dropdowns show additional instances.

The repository `.jump.repo-add-file` button is also assigned `role=menu`; axe reports `button-name` there. Source inspection found a localized visible Add File label in `templates/repo/view_content.tmpl`, while the shared dropdown patch overrides its role. This symptom is consolidated here rather than counted as a separate unnamed-button defect. Its exact HTML/checks remain in the axe evidence.

Impact: assistive technology receives invalid menu structure. No claim of complete keyboard failure or a completed screen-reader audit is made.

Evidence: [exact HTML/selectors](../evidence/axe-findings.json), [login screenshot](../evidence/screenshots/journeys-axe-user-login.png), [JUnit](../evidence/playwright-junit.xml), [exploratory DOM corroboration](../exploratory/session-03.md).

Duplicate check: ARIA/menu searches found no exact current markup report. [Historical issue 7057](https://github.com/go-gitea/gitea/issues/7057) concerned click-oriented dropdowns in 1.8.1; [29849](https://github.com/go-gitea/gitea/issues/29849) tracks component replacement. Link that history when filing. [Search record](upstream-search.md).

Fix scope: shared role/keyboard/active-descendant behavior needs coordinated frontend changes and regressions; a footer-only attribute change would not fix the root cause.
